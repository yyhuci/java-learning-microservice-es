## 阶段一：建立全局地图

### 架构为什么一步步演进到微服务

- 单体应用把所有业务放在一个工程和一个部署单元中，开发初期简单，但随着业务增长会出现代码耦合、发布互相影响和无法按业务独立扩容的问题。
- 垂直拆分把不同业务分成多个服务，使用户、商品、订单等模块可以独立开发、部署和扩容。
- 服务拆分后也带来远程调用、服务发现、故障隔离、分布式事务和监控等新问题，因此需要 Spring Cloud Alibaba 等微服务基础设施。

### 微服务常用术语地基

- **服务注册与发现**：Nacos 让服务注册自己的地址，其他服务可按服务名查找并调用它。
- **网关（Gateway）**：客户端统一入口，负责路由、鉴权等横向能力。
- **OpenFeign**：用接口声明的方式完成服务间远程 HTTP 调用。
- **限流**：限制单位时间请求量，保护服务不被突发流量压垮。
- **熔断**：下游连续故障时暂时停止调用，防止故障扩散；恢复时可经过半开状态逐步尝试。
- **降级**：依赖不可用时返回可接受的备用结果，保证核心链路仍能响应。
- **Seata 分布式事务**：协调多个服务的本地事务；微服务中也常通过重试、幂等和最终一致性处理跨服务数据。
- **Redis**：用于缓存、热点数据和分布式锁等高频场景。

### Elasticsearch 的定位

- MySQL 是业务数据的主要事实来源，适合事务和精确查询；Elasticsearch 面向复杂检索、全文搜索、筛选和聚合。
- Elasticsearch 依靠**倒排索引**提升文本检索速度：由“词”找到包含该词的文档。
- 字段通常区分为 `text`（分词后的全文检索）与 `keyword`（精确匹配、排序、聚合）。
- 集群基本概念包括节点、分片和副本；健康状态中，`green` 表示主分片和副本均正常，`yellow` 表示主分片正常但部分副本未分配，`red` 表示存在主分片不可用。

## 核心知识点

- Maven 父工程使用 `packaging` 为 `pom`，通过 `<modules>` 管理子模块。
- Spring Boot 父工程负责统一依赖版本、插件和 Java 构建配置。
- 子模块通过 `<parent>` 继承父工程，`relativePath` 指向上级 `pom.xml`。
- `Result<T>` 中的 `T` 是泛型类型占位符，可让同一个返回对象承载不同业务数据类型。
- `private` 字段体现封装，外部通过 getter/setter 读取和修改数据。
- `static` 工厂方法可使用 `Result.success(...)`、`Result.fail(...)` 直接创建返回对象。
- JUnit 使用 `@Test` 标记测试方法，使用 `assertEquals`、`assertNull` 验证结果。
- 实体类常用包装类型 `Long`、`Integer`，因为它们可以表示 `null`。
- 金额应使用 `BigDecimal`，推荐 `new BigDecimal("5999.00")`，不要使用 `new BigDecimal(5999.00)`。
